# 요청서: 악보집에 "🎹 반딧불 앨범 받기" 버튼

- **보내는 곳:** 작곡 세션 (브랜치 `claude/piano-composition-am-gbafho`)
- **받는 곳:** 뮤직랩 원장님 (앱 개발 세션)
- **날짜:** 2026-11-15
- **사용자 요청:** "작곡 세션에서 만든 곡을 악보집에 '기타' 카테고리로 자동으로 넣고 싶다."

## 1. 배경

- 작곡 세션은 사용자를 위해 피아노 창작곡을 `scores/*.abc`로 만들고 있습니다(현재 81곡). 사용자는 지금까지 이 곡들을 악보집(`library.html`)에 손으로 하나씩 '기타' 카테고리로 넣어 왔고, 그래서 빠진 곡이 생겼습니다. 9월 27일 드라이브 동기화본 기준으로 73~81번 9곡이 빠져 있었습니다.
- 바깥에서 사용자의 드라이브 파일에 곡을 넣는 방법은 쓸 수 없습니다. 악보집의 드라이브 연동은 `drive.file` 범위라서, 다른 클라이언트가 만든 파일은 앱에 보이지 않습니다. 또 작곡 세션의 드라이브 도구로는 기존 파일의 내용을 고칠 수 없습니다.
- 그래서 **앱 안에서** 저장소의 곡 목록을 읽어 와 없는 곡만 넣는 버튼을 요청드립니다. 앱 안에서 저장하므로 기존 드라이브 동기화가 그대로 작동합니다.
- 임시 조치로, 사용자에게는 빠진 9곡을 담은 가져오기용 JSON을 보냈습니다. 이 9곡의 id는 아래 목록과 같은 `fireflies-album-073` ~ `fireflies-album-081`입니다. 사용자가 이 파일을 먼저 불러왔더라도 버튼은 이 9곡을 "이미 있음"으로 처리해야 합니다.

## 2. 사용자 시나리오

1. 악보집에서 **[🎹 반딧불 앨범 받기]**를 누른다.
2. 확인 화면에 **악보집에 없는 곡만** 번호, 제목과 함께 나온다. 체크박스는 기본으로 모두 선택돼 있고, "이미 있는 72곡은 건너뜁니다"처럼 건너뛰는 곡 수도 보인다.
3. **[추가]**를 누르면 선택한 곡이 '기타' 카테고리로 저장되고, "9곡을 추가했어요 ✓"가 뜬다.
4. 평소처럼 드라이브에 저장하면 다른 기기에도 들어간다.
5. 버튼을 다시 눌러도 중복이 생기지 않는다. 새 곡이 없으면 "새 곡이 없어요. 81곡이 모두 들어 있어요"가 뜬다.

## 3. 데이터: `scores/album.json` (작곡 세션이 관리)

작곡 세션 브랜치에 이미 만들어 두었습니다. 새 곡을 만들 때마다 작곡 세션이 이 파일에 한 줄씩 추가합니다(CLAUDE.md에 적어 둔 규칙).

```json
{
  "album": "반딧불 앨범",
  "category": "기타",
  "updated": "2026-11-15",
  "count": 81,
  "tracks": [
    {"no": 1, "id": "fireflies-album-001", "title": "퇴근길의 반딧불", "file": "fireflies-way-home.abc"},
    {"no": 81, "id": "fireflies-album-081", "title": "퇴근길의 반딧불 (풀버전)", "file": "fireflies-way-home-full.abc"}
  ]
}
```

- `id`: 곡마다 고정된 값입니다. 악보집 항목의 `id`로 그대로 써 주세요.
- `title`: 그 `.abc` 파일의 첫 번째 `T:` 줄과 같습니다. 'ABC 불러오기'가 붙이는 제목과도 같습니다.
- `file`: `scores/` 폴더 안의 파일 이름입니다.
- 81곡의 제목은 서로 겹치지 않습니다.

## 4. 구현 요청

1. **버튼 위치:** `library.html` 툴바의 '🎼 ABC 불러오기' 옆.
2. **목록 읽기:** 같은 사이트의 상대 경로로 `fetch('scores/album.json?t=' + Date.now())`. 실패하면(오프라인, 파일 없음, 형식 오류) 이유를 알려 주는 메시지만 띄우고 악보집은 건드리지 않습니다.
3. **이미 있는 곡 판정:** 순수 함수로 만들어 `LibraryCore`에 넣어 주시면 테스트하기 좋습니다(예: `LibraryCore.albumDiff(entries, tracks)` → `{ fresh: [...], present: [...] }`).
   - 악보집 항목의 `id`가 트랙 `id`와 같으면 있음.
   - 아니면 제목을 정규화(앞뒤 공백 제거, 연속 공백을 하나로)해서 같으면 있음. 사용자의 기존 72곡은 무작위 id라서 제목으로만 맞습니다.
   - 둘 다 아니면 새 곡.
4. **추가:** 선택한 곡마다 `fetch('scores/' + file)` → `LibraryCore.splitAbcTunes(text, title)[0].abc` → `entries.push({ id: track.id, title: track.title, abc: abc, cat: '기타', added: Date.now() })` → `save(); render();`. 일부 파일을 못 받으면 받은 곡만 저장하고, 실패한 곡 목록을 보여 주세요.
5. **덮어쓰지 않기:** 이미 있는 곡은 손대지 않습니다. 사용자가 악보집에서 직접 고친 곡(템포 추가 등)이 있기 때문입니다.
6. **(선택, 2단계) 바뀐 곡:** `id`가 같은데 `abc`가 다른 곡을 "업데이트된 곡 N곡"으로 따로 보여 주고, 사용자가 고른 곡만 바꿉니다.
7. **(선택) 새 곡 알림:** 페이지를 열 때 조용히 `album.json`을 확인해서 버튼에 "새 곡 N" 배지를 답니다. 자동으로 추가하지는 않습니다.

- `tests/library-e2e.test.mjs`에서 `album.json`과 `.abc` 요청을 가짜 응답으로 바꿔 다음을 확인해 주세요.

  - 기존 항목의 `abc`가 그대로인지

## 6. 완료 기준

1. 악보집에 없는 곡만 '기타'로 추가된다.
2. 여러 번 눌러도 중복이 생기지 않는다.
3. 이미 있는 곡의 내용이 바뀌지 않는다.
4. 드라이브에 저장한 뒤 다른 기기에서 불러오면 새 곡이 보인다.
5. 기존 테스트가 모두 통과한다.

## 7. 배포 관련 (중요)

- `scores/album.json`과 46~81번 악보 파일은 **아직 main에 없습니다.** 작곡 브랜치 `claude/piano-composition-am-gbafho`에만 있고, main의 `scores/`에는 45곡만 있습니다.
- 기능 개발과 테스트는 위 형식의 가짜 데이터로 진행해 주세요. 실제 사이트에서는 작곡 브랜치가 main에 합쳐진 뒤부터 작동합니다. 합치는 PR은 사용자가 작곡 세션에 따로 요청할 예정입니다.
- 확인 부탁드립니다: 사이트가 어느 브랜치와 경로에서 배포되는지, 그리고 `library.html` 기준으로 `scores/album.json` 상대 경로가 맞는지.

## 8. 참고: 현재 악보집 구조 (작곡 세션이 코드를 읽고 정리한 내용)

- localStorage `broguard_library`에는 `LibraryCore.serialize(entries)`, 즉 `{ app: 'broguard-library', v: 1, entries: [{ id, title, abc, cat, added }] }`가 저장됩니다.
- `LibraryCore.CATS`에 '기타'가 있고, `normCat()`은 모르는 분류를 '기타'로 바꿉니다.
- 드라이브 합치기는 `LibraryCore.mergeEntries`를 씁니다. id가 같거나 제목과 abc가 모두 같으면 건너뜁니다. 그래서 고정 id를 쓰면 기기 사이에서도 중복이 생기지 않습니다.
- '⬆ 백업 불러오기'는 중복 검사를 하지 않아서, 같은 파일을 두 번 불러오면 곡이 두 번 들어갑니다. 이번 기능은 이 문제가 없어야 합니다.
