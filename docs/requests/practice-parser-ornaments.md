# 요청서: 피아노 교실에서 두 손이 어긋나는 문제 (꾸밈음, 중간 조 바꿈, 짧은 음표)

- **보내는 곳:** 작곡 세션 (브랜치 `claude/piano-composition-am-gbafho`)
- **받는 곳:** 뮤직랩 원장님 (앱 개발 세션)
- **날짜:** 2026-11-21
- **사용자 제보:** "미뉴에트 G장조를 다시 받았어요. 거기에 꾸밈음이라고 해야 하나요? 이것 때문인 것 같기도 하고요. 왼손 오른손이 각자 놀아요."

## 1. 증상

- 피아노 교실(`practice.html`)에서 「바흐 · 미뉴에트 G장조 [3 원곡]」을 들어 보거나 연습하면 3마디부터 오른손이 왼손보다 늦어집니다. 꾸밈음이 나올 때마다 더 밀려서, 곡 끝에서는 1마디 반이 어긋납니다.
- **뮤직랩과 악보집(abcjs 재생)에서는 정상입니다.**
  - abcjs `setUpAudio()`로 확인하니, 꾸밈음은 뒤 음의 시간을 빌려 쓰고 마디마다 두 손이 정확히 맞습니다.
  - 그래서 악보 파일이 아니라 피아노 교실의 악보 읽기 쪽 문제로 봤습니다.

## 2. 원인: `practice.html`의 `parseSong()` → `parseBody()` 정규식 (376줄 부근)

```js
var re = /"([^"]*)"|!([^!\s]*)!|(\|)|\[([^\]\[:]+)\](\d*)(?:\/(\d+))?(-?)|([_^=]?)([A-Ga-gz])([,']*)(\d*)(?:\/(\d+))?(-?)/g
```

이 정규식에서 생기는 문제가 세 가지입니다. 아래 결과는 작곡 세션이 Playwright로 `window.__practice.parseSong()`을 직접 호출해 확인한 값입니다.

### 2-1. 꾸밈음 `{…}`을 보통 음표로 읽음 (오른손이 밀림)

- `{` `}`는 건너뛰지만, 그 안의 음 글자는 L 길이의 보통 음표로 읽힙니다.
- 예: `L:1/8`에서 `"C"e2 {cB}cdef`를 읽으면, 꾸밈음 도와 시가 8분음표 두 개(1박)로 끼어듭니다.
- 미뉴에트 G장조 원곡의 경우:
  - 오른손이 201칸, 왼손이 192칸으로 읽힙니다. 정답은 둘 다 192칸입니다.
  - 차이 9칸은 꾸밈음 `{cB}` 4개와 `{B}` 1개의 음 수와 같습니다.

### 2-2. 곡 중간의 조 바꿈 `[K:…]`을 처리하지 않음 (틀린 음과 없는 음)

- `\[([^\]\[:]+)\]`가 콜론 때문에 맞지 않습니다. 그러면 필드 안의 글자가 음표로 읽힙니다. 예를 들어 `[K:D]`의 `D`가 "레" 음표가 됩니다.
- 새 조표도 적용되지 않습니다. 임시표는 머리의 `K:`(`acc`)만 씁니다.
- 재현:
  ```
  K:C
  [V:1] F2 F2 F2 F2 | [K:D] F2 F2 F2 F2 |]
  ```
  - 지금 결과: `파4(65)×4, 레4(62)@8, 파4(65)×4`. 없는 '레'가 끼고, D장조 구간의 F가 F#(66)이 아닌 F(65)로 남습니다.
  - 기대 결과: `파4(65)×4, 파#4(66)×4`.
- 두 성부에 모두 `[K:]`가 들어가서 두 손이 같은 길이만큼 밀립니다. 그래서 어긋남은 드러나지 않지만, 조를 옮긴 구간의 음이 틀립니다.

### 2-3. L보다 짧은 음표를 L 한 칸으로 셈 (반 박 밀림)

- 칸 단위가 L이어서, `L:1/8`의 `c/d/`(16분음표 두 개)가 2칸으로 계산됩니다. 정답은 1칸입니다.
- `/` 뒤에 숫자가 없는 `c/`는 길이 1로 읽히고, `c/2`처럼 숫자가 있어도 `Math.max(1, …)` 때문에 1칸 아래로 내려가지 않습니다.
- 미뉴에트 G단조 [2], [3]의 31마디 `c/d/`에서 오른손이 반 박 밀립니다.

## 4. 고치는 방법 제안 (방식은 원장님이 정해 주세요)

1. **꾸밈음:** 정규식 맨 앞에 `\{[^}]*\}` 갈래를 넣고 건너뜁니다.
   - 칸(박자) 계산에는 넣지 않습니다.
   - 레인에 작은 음으로 보여 주거나 들어보기에서 짧게 울리는 것은 선택입니다. 사용자가 꾸밈음을 따로 치지 않아도 판정이 넘어가야 합니다.
2. **인라인 필드:** `\[([A-Za-z]):([^\]]*)\]` 갈래를 넣습니다.
   - `K`이면 `acc`를 새 조로 바꾸고 `measureAcc`를 초기화합니다. 조 이름 뒤의 글자는 무시합니다(`KEY_ACCIDENTALS` 조회 전 첫 단어만).
   - `Q`, `M`, `L` 등 나머지는 일단 건너뜁니다. `[Q:]` 템포 변화를 반영하는 것은 선택입니다.
   - 사용하는 곳: `[K:]`는 위 20곡에서, `[M:]`은 `like-an-old-film-full.abc`(4/4 ↔ 3/4)에서, `[Q:]`는 6곡의 rit.와 템포 변화에서 씁니다.
3. **짧은 음표:** 다음 둘 중 하나를 골라 주세요.
   - 내부 칸 단위를 L보다 잘게 셉니다(예: L의 1/4). 표시는 지금처럼 하면 됩니다.
   - 이미 있는 `abcjsFallback()`처럼 abcjs 파싱 결과를 기본으로 씁니다. abcjs 쪽은 꾸밈음과 조 바꿈도 이미 맞게 처리합니다.

작곡 세션은 앞으로도 꾸밈음 `{}`와 조 바꿈 `[K:]`를 씁니다. 반음 위아래로 떠는 꾸밈은 abcjs의 장식 기호가 틀린 음을 내서 `{cB}c`처럼 꾸밈음으로 적어야 하기 때문입니다.

## 5. 테스트 제안 (`tests/practice-e2e.test.mjs`)

- `L:1/8`, `[V:1] {cB}c2 d2 |`
  - 음은 2개(도, 레)여야 합니다.
  - 칸 합은 4여야 합니다.
- `K:C`, `[V:1] F2 | [K:D] F2 |]`
  - 두 번째 음이 66(파#)이어야 합니다.
  - 음은 2개뿐이어야 합니다.
- `L:1/8`, `[V:1] c/d/ e |`
  - c와 d가 각각 반 칸이어야 합니다(칸 단위를 바꾸면 그 단위로).
  - 다음 음 e가 1칸 위치에서 시작해야 합니다.
- **회귀 검사:** 저장소의 두 성부 악보 전체에 대해 `seq`와 `bassSeq`의 끝 위치(`start + len`의 최댓값)가 같은지 확인합니다. 지금은 위 9곡이 다릅니다.
  ```js
  const s = window.__practice.parseSong(abc);
  const end = q => (q || []).reduce((m, n) => Math.max(m, n.start + n.len), 0);
  // end(s.seq) === end(s.bassSeq)
  ```

## 6. 완료 기준

1. 3장의 9곡에서 두 손의 길이가 같다(피아노 교실에서 두 손이 함께 끝난다).
2. `[K:]`가 있는 20곡에서 조 바꿈 뒤의 샵과 플랫이 맞고, 없는 음이 끼지 않는다.
3. 꾸밈음이 있는 곡을 연습할 때 꾸밈음을 치지 않아도 다음 음으로 넘어간다.
4. 기존 테스트가 모두 통과한다.

## 7. 참고

- 악보 파일은 고치지 않았습니다. 뮤직랩과 악보집의 abcjs 재생에서는 두 손이 맞습니다.
- 사용자에게는 고쳐지기 전까지 미뉴에트 G장조 원곡을 뮤직랩에서 듣고, 피아노 교실에서는 1, 2단계(꾸밈음 없음)로 연습하도록 안내했습니다.
- 검사 방법:
  1. Playwright로 `practice.html`을 열고 abcjs CDN 요청은 로컬 abcjs 6.5.2로 대신합니다.
  2. 각 `.abc`를 `window.__practice.parseSong()`에 넣어 위 회귀 검사와 같은 값을 비교했습니다.
